01 / Ask your website

Spot the leak

app.js (runs in the browser)
fetch(aiUrl, {
  headers: {
    Authorization: 'Bearer ' + MY_KEY
  }
})
Leak or safe?

Leak

Anyone can open the browser's developer tools and copy the key.

api/chat.mjs (runs on Vercel)
const key =
  process.env.AI_GATEWAY_API_KEY;
Leak or safe?

Safe

The key is read on the server from Vercel settings. Visitors never receive it.

A Git commit
git add .env.local
git commit -m "setup"
git push
Leak or safe?

Leak

The key is now in GitHub history. Rotate it, then add .env.local to .gitignore.

Decide for each card first. Then open it to check.

Lab 3: Make the real change

15 min

Goal

"Which colour options are available?" gets a sourced answer, and nothing else changes.

Done when

The colour answer cites Palette choices. The refund question is still unknown.

  1. Check the truth first: core.js lists ember, blue and lime.
  2. Ask the agent to add sources/palettes.md, wiki/palettes.md and a manifest entry.
  3. Update checks/questions.json so the colour question expects palettes.
  4. Review the diff yourself, then run: npm run approve-content -- palettes
  5. Run build, check and test. Ask the question again.

What the change looks like

wiki/manifest.json / add
{
  "id": "palettes",
  "title": "Palette choices",
  "file": "palettes.md",
  "source": "sources/palettes.md",
  "verifiedOn": "2026-10-15",
  "public": true

checks/questions.json / change
{
  "question":
    "Which colour options are available?",
- "expectSource": null
+ "expectSource": "palettes",
+ "mustInclude": "Ember"
}

approve-content adds the review hashes for you. Never type them by hand.
